# Семантика языка

## 1. Общая модель языка

Язык является преимущественно функциональным, статически типизированным
языком с лексической областью видимости, eager-вычислением в базовой версии
и возможностью расширения до lazy evaluation.

Базовые свойства:
- значения неизменяемы по умолчанию
- функции являются значениями первого класса
- функции могут передаваться как аргументы, возвращаться из других функций
  и связываться с именами
- разрешение имён производится по ближайшей охватывающей области

Внутри функционального ядра предпочтительны чистые функции.
Однако язык допускает встроенные функции с побочными эффектами
(print, input, exit, panic), а также ограниченную мутабельность через mut.

---

## 2. Стратегия вычисления

### 2.1. Базовая стратегия

В базовой версии языка используется call-by-value:
- аргументы функции вычисляются перед вызовом функции
- аргументы передаются по значению
- значения выражений вычисляются слева направо

Это означает, что в вызове:

f(a(), b())

сначала вычисляется a(), затем b(), затем вызывается f.

### 2.2. Расширение: ленивые вычисления

В расширенной версии языка допускается поддержка lazy evaluation
для пользовательских значений, списков и pattern matching.

В этом режиме:
- выражение может быть представлено thunk-объектом
- вычисление выполняется только в момент, когда значение действительно требуется
- результат вычисления мемоизируется

Ленивость не отменяет статическую типизацию:
тип выражения определяется на этапе компиляции, даже если само значение
будет вычислено позже.

*семантический анализатор определяет тип каждого выражения до генерации кода

## 3. Значения и связывания

### 3.1. let

let создаёт неизменяемое имя.
После связывания имени с выражением переприсваивание невозможно.

Пример:

let x = 5 in x + 1

Имя x обозначает значение 5 и не может быть изменено.

### 3.2. mut

mut создаёт изменяемую переменную.
Присваивание допустимо только для имён, введённых через mut,
если оператор присваивания включён в расширенную версию языка.

Пример:

mut counter = 0

В чисто функциональном подмножестве языка mut не используется.
Он сохраняется как допускаемое расширение для встроенных механизмов
или ограниченных императивных фрагментов.

Примечание:
Возможно, будет реализован в продвинутой версии языка

### 3.3. Использование до объявления

Использование идентификатора до его объявления запрещено
и является ошибкой семантического анализа.

### 3.4. Shadowing

Перекрытие имён допускается:
внутреннее объявление скрывает внешнее в пределах своей области видимости.

Повторное объявление одного и того же имени в одной и той же области запрещено.

## 4. Функции

### 4.1. Функции как значения

Функция является значением первого класса.
Её можно:
- передать как аргумент
- вернуть из другой функции
- связать с именем

### 4.2. Применение функций

При вызове функции:
1. вычисляется выражение функции
2. вычисляются аргументы
3. создаётся новая область видимости
4. параметры связываются с переданными значениями
5. вычисляется тело функции

### 4.3. Замыкания

Если функция определена в окружении, содержащем свободные переменные,
она захватывает их по значению в момент создания функции.

Пример:

let add = \x -> (\y -> x + y)

Внутренняя функция хранит значение x внутри замыкания.

### 4.4. Рекурсия

Функции могут быть рекурсивными.
Имя функции доступно внутри её собственного тела.

В расширенной версии допускается взаимная рекурсия между группой функций,
объявленных в одном модуле.

### 4.5. Возвращаемое значение функции

В языке отсутствует ключевое слово return.
Результатом функции является значение выражения,
составляющего тело функции.

Пример:

fn inc(x: int64) -> int64 = x + 1

Функция возвращает значение выражения x + 1.

## 5. Система типов

### 5.1. Общие свойства

Система типов является статической:
типы всех выражений определяются или проверяются на этапе компиляции.

Компиляция завершается ошибкой, если:
- операция применена к аргументам неподходящего типа
- типы ветвей условного выражения несовместимы
- функция вызвана с неверным числом аргументов
- функция вызвана с аргументами неверного типа
- pattern matching некорректен относительно типа сопоставляемого значения

### 5.2. Базовые встроенные типы

Поддерживаются:
- целые типы
- беззнаковые целые типы
- вещественные типы
- bool
- string
- unit
- списки
- кортежи
- ADT
- функциональные типы

пояснение:
Вместо массивов фиксированного размера язык использует связные списки как основную коллекцию. Списки динамические и поддерживают сопоставление с образцом через cons-паттерн.

### 5.3. Вывод типов

Если тип локального значения может быть однозначно определён из выражения справа,
допускается его автоматический вывод.

Пример:

let x = 42 in x

Компилятор выводит:
x : int64

Для функций верхнего уровня допускается как явная аннотация типа,
так и вывод типа из тела функции, если реализация это поддерживает.

### 5.4. Явные приведения

В базовой версии языка неявные приведения типов не выполняются.
Если поддержка явных приведений будет добавлена, они должны быть явно
зафиксированы в синтаксисе и системе типов.

### 5.5. Совместимость типов

В базовой версии допускается номинальная совместимость пользовательских типов:
два объявленных типа считаются различными, даже если их внутренняя структура совпадает.

Синоним типа не создаёт нового типа.

## 6. Условные выражения и локальные связывания

### 6.1. if

Выражение:

if cond then e1 else e2

имеет корректную семантику, если:
- cond имеет тип bool
- e1 и e2 имеют один и тот же тип, либо совместимые типы по правилам системы типов

Результатом выражения является значение той ветви, условие которой было выбрано.

### 6.2. let-in

Выражение:

let x = e1 in e2

вычисляет e1, связывает его результат с именем x,
после чего вычисляет e2 в расширенном окружении.

Имя x видно только внутри e2.

## 7. Pattern matching

### 7.1. Общая семантика

match вычисляет сопоставляемое выражение один раз,
после чего последовательно проверяет ветви сверху вниз.

Первая подходящая ветвь выбирается и вычисляется.
Если ни один шаблон не подходит, возникает runtime error

### 7.2. Связывание имён

Имена, появляющиеся в шаблоне, вводят новые локальные связывания,
доступные только внутри соответствующей ветви.

Пример:

match value {
  Some(x) -> x + 1,
  None -> 0
}

В первой ветви x связано со значением, находящимся внутри Some.

### 7.3. Проверка типов в pattern matching

Шаблон обязан соответствовать типу сопоставляемого выражения.

Примеры:
- для Option[int64] допустимы шаблоны Some(x) и None
- для Result[int64, string] допустимы Ok(v) и Err(err)
- для кортежа (int64, bool) допустим шаблон (x, flag)

Использование конструктора, не принадлежащего типу выражения,
является ошибкой компиляции.

## 8. Встроенные функции

### 8.1. print

print(x) выводит значение x в стандартный поток вывода.
Возвращаемое значение — unit.

### 8.2. input

input() читает одну строку из стандартного потока ввода.
Возвращаемое значение — string.

### 8.3. exit

exit(code) немедленно завершает программу с указанным кодом возврата.

### 8.4. panic

panic(msg) аварийно завершает программу с диагностическим сообщением.

### 8.5. map

map(f, xs) применяет функцию f ко всем элементам списка xs
и возвращает новый список результатов.

Тип:
map : (a -> b, List[a]) -> List[b]

### 8.6. filter

filter(pred, xs) применяет предикат pred ко всем элементам списка xs
и возвращает новый список тех элементов, для которых pred вернул true.

Тип:
filter : (a -> bool, List[a]) -> List[a]

### 8.7. foldl

foldl(f, init, xs) последовательно сворачивает список слева направо.

Тип:
foldl : ((b, a) -> b, b, List[a]) -> b

Примечание: map, filter, foldl будут реализованы в 
продвинутой версии языка

---

## 9. Побочные эффекты

Хотя язык функциональный по стилю, он не является строго чистым:
- ввод/вывод разрешён через builtins
- завершение программы через exit/panic является наблюдаемым эффектом
- ограниченная мутабельность через mut допускается как расширение

В дальнейших версиях языка побочные эффекты могут быть изолированы

---

## 10. Ошибки времени выполнения

При runtime error выполнение программы прекращается.
Сообщение об ошибке имеет вид:

runtime error: <сообщение> at line <N>

Минимально обязаны диагностироваться:
- деление на ноль
- ошибка сопоставления без подходящей ветви, если она не была исключена статически

Дополнительно можно диагностировать:
- ошибки встроенных функций, связанные с некорректными аргументами

---

## 11. Точка входа

Программа обязана содержать функцию:

fn main() -> int64 = ...

Функция main:
- должна быть объявлена на верхнем уровне
- не принимает аргументов
- возвращает код завершения процесса
