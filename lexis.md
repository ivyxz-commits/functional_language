# Лексика языка

## 1. Общие положения

Язык является статически типизированным функциональным языком программирования,
неизменяемыми значениями по умолчанию, first-class functions, algebraic data types, pattern matching и синтаксисом,
частично вдохновлённым Haskell.

Исходный текст программы интерпретируется как последовательность ASCII-символов.
В базовой версии языка допускаются только ASCII-символы во всех лексических
единицах исходного кода, включая комментарии и строковые литералы.

Лексический анализатор преобразует исходный текст в поток токенов.
Пробельные символы и комментарии в поток токенов не передаются, кроме случаев,
когда позиция токена требуется для диагностики ошибок.

---

## 2. Базовые классы символов

LETTER      ::= [A-Za-z_]
DIGIT       ::= [0-9]
WS          ::= [ \t\r\n]+
NONQUOTE    ::= любой ASCII-символ, кроме " и перевода строки
ESCAPE      ::= '\' ('n' | 't' | '"' | '\' | 'r')

---

## 3. Комментарии

Поддерживаются однострочные комментарии:

COMMENT ::= '//' любой_ASCII_символ_кроме_перевода_строки*

Комментарий продолжается до конца строки и игнорируется лексером.

---

## 4. Идентификаторы

IDENT ::= LETTER (LETTER | DIGIT)*

Идентификаторы используются для:
- имён функций
- имён параметров
- локальных имён
- имён пользовательских типов
- имён конструкторов
- имён полей структур

Идентификатор не может совпадать с зарезервированным ключевым словом.

Рекомендуемое соглашение:
- имена значений и функций: lowerCamelCase или snake_case
- имена типов и конструкторов: PascalCase

## 6. Литералы

### 6.1. Целые литералы

INT ::= DIGIT+

Целочисленный литерал по умолчанию имеет тип int64, если иное не следует
из контекста или из явного приведения типа.

### 6.2. Вещественные литералы

REAL ::= DIGIT+ '.' DIGIT+

Вещественный литерал по умолчанию имеет тип float64 / real64.

### 6.3. Строковые литералы

STRING ::= '"' (NONQUOTE | ESCAPE)* '"'

Поддерживаются escape-последовательности:
- \n
- \t
- \r
- \"
- \\

Строковые литералы в базовой версии языка содержат только ASCII-символы.

### 6.4. Булевы литералы

BOOL ::= 'yep' | 'nope'

## 8. Приоритет операторов

От большего приоритета к меньшему:

1. primary
2. postfix:
   - вызов функции
   - индексирование
   - доступ к полю
   - доступ к имени из модуля
3. unary:
   - унарный минус
   - not
4. multiplicative:
   * / %
5. additive:
   + -
6. comparison:
   < > <= >=
7. equality:
   == !=
8. logical_and:
   and
9. logical_or:
   or

Операторы одного уровня приоритета являются левоассоциативными,
если явно не указано иное.

---

## 9. Разделение токенов

Если два соседних фрагмента исходного текста могут быть интерпретированы
двумя способами, лексер использует правило максимального совпадения:
выбирается наиболее длинная допустимая лексема.

Примеры:
- >= распознаётся как один токен, а не как '>' и '='
- == распознаётся как один токен, а не как два '='
- -> распознаётся как один токен, а не как '-' и '>'


## 10. Ограничение кодировки

Базовая версия языка использует только ASCII.

Это означает:
- ключевые слова, идентификаторы, операторы и разделители состоят только из ASCII-символов
- комментарии состоят только из ASCII-символов
- строковые литералы состоят только из ASCII-символов
- поддержка Unicode и UTF-8 не требуется

Если в исходном файле встречается не-ASCII символ, это считается лексической ошибкой.

---

## 11. Ошибки лексического анализа

Лексической ошибкой является:
- неизвестный символ
- не-ASCII символ в исходном тексте
- незавершённая строка
- недопустимая escape-последовательность
- недопустимый числовой литерал

При лексической ошибке компилятор завершает анализ и выводит сообщение вида:

<файл>:<строка>:<столбец>: error: lexical error: <сообщение>
