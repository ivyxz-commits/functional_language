## 1. Целевая платформа

- x86-64
- синтаксис ассемблера NASM
- соглашение о вызовах System V ABI

---

## 2. Этапы компиляции

Компилятор работает как последовательный pipeline:

source -> lexer -> parser -> typed AST -> lowering -> asm

То есть:

- исходный текст преобразуется в поток токенов
- поток токенов преобразуется в AST
- AST проходит семантический анализ и аннотируется типами
- typed AST понижается в более удобное для кодогенерации представление
- затем генерируется x86-64 assembly

---

## 3. Представление значений во время выполнения

Во время выполнения значения представляются следующим образом:

- int64 - непосредственное целое значение или значение в регистре
- bool - целое значение 0 или 1
- unit - специальное значение без полезной нагрузки
- string - указатель на строковые данные и, при необходимости, длина строки
- closure - пара из указателя на код функции и указателя на окружение
- ADT - tagged representation, то есть значение хранит тег конструктора и связанные данные
- list - список представляется как размещённые в куче cons-ячейки

---

## 4. Вызовы функций

Вызовы функций реализуются по правилам System V ABI:

- первые аргументы передаются через регистры
- оставшиеся аргументы передаются через стек
- возвращаемое значение помещается в регистр rax

Для пользовательских функций и встроенных функций используется единая базовая схема вызова,
если иное не оговорено отдельно.

---

## 5. Замыкания

Лямбда-выражения и функции, захватывающие внешние переменные, реализуются как замыкания.

Замыкание содержит:

- указатель на машинный код функции
- указатель на объект окружения

Окружение хранит значения всех захваченных переменных.

При вызове замыкания:

- извлекается указатель на код
- извлекается указатель на окружение
- окружение передаётся в сгенерированную функцию как скрытый аргумент

---

## 6. Pattern matching

Сопоставление с образцом компилируется в последовательность:

- проверок тега значения
- сравнений литералов
- переходов по условию
- извлечения полей конструктора

Для ADT используется анализ тега конструктора.
Для кортежей, списков и литеральных шаблонов генерируются соответствующие проверки и переходы.

---

## 7. Встроенные функции

Язык поддерживает встроенные функции:

- print
- input
- exit
- panic

Также встроенные функции высшего порядка, такие как map и filter, могут быть реализованы одним из двух способов:

- как runtime helpers, то есть как заранее написанные функции среды выполнения
- как специальные встроенные конструкции, для которых компилятор генерирует код напрямую

Базовая версия проекта может использовать первый вариант как более простой в реализации.

---

## 8. Ошибки времени выполнения

Во время выполнения должны обрабатываться как минимум следующие ошибки:

- деление на ноль
- выход за допустимые границы структуры данных
- неуспешное сопоставление в match, если ситуация не была исключена статически

При возникновении такой ошибки выполнение программы прекращается,
и пользователю выводится диагностическое сообщение.
